# Bugbot review guide for loop-pi

## What this is

A public repository. TypeScript pi extensions in `extensions/` (loop-guard, loop-wait,
loop-continuation, loop-state, loop-status, request-ceiling, call-timing, lane-worktrees), agent
files and settings in `home/`, and Python tools in `bin/` (installer, preflight, audit, nopush
launcher wrapper, leak scan). `extensions/SEAMS.md` is the contract between the extensions;
`AGENTS.md` holds the repository rules.

## Invariants to defend

- **A seam changes in `extensions/SEAMS.md` first, then in every extension it touches.** Flag a
  behaviour change to a seam (closeout counting, launch arming, run-dir files, root recovery,
  request ceiling, names and paths) with no matching SEAMS.md edit or no test.
- **Only the root pushes.** The lane guard refuses every `git push`; force, delete and mirror
  pushes are refused for every role. `bin/loop-pi-nopush` pins `pushInsteadOf` for `https://`,
  `http://` and `ssh://` so background runners cannot push. Flag anything that widens a push
  route, grants a lane push identity (`push-grant.ts` binds identity and run dir only), or lets a
  `subagent` call override the pinned model or run deadline.
- **The guard is an honest-mistake fence, not a security boundary.** Do not ask for a
  sandbox. Do flag a rule that stops matching a plainly typed command it used to block, and a
  parser change that makes unparseable input fail closed instead of taking the conservative
  fallback scan.
- **One model family.** `model-family.ts` refuses any model outside the configured family, in the
  root and every lane. Flag a default family, root route or agent file that names a model outside it.
- **Project trust stays `never`** (`home/settings.json`), so a child does not load the target
  repository's `.pi/`, skills or extensions. Flag a `skills` path or a trust change in the home.
- **Tests never call a live model and never touch `~/.pi`.** They use the scripted `faux`
  provider with a fresh temporary `PI_CODING_AGENT_DIR`. Flag a test that reaches a real provider
  or an installed home, and a fixture removed before its child has a readiness signal.
- **Recorded guard verdicts are pinned.** `rules.test.ts` pins every row of
  `extensions/loop-guard/fixtures/real-lane-blocks.json`. A flipped verdict needs the commit to say
  so and the fixture expectation updated on purpose.
- **Leak gate.** Nothing private may be committed: no hostname, address, tenant or account id,
  person's name or email, internal task id or credential path. `bin/leak-scan` fails closed (exit
  2) with no term source, an empty list or a shallow clone. Flag any loosened pattern in
  `leak-patterns.public.txt`, a new `leak-scan.binary-allow` entry, a `--no-verify`, a
  `core.hooksPath`, or a secret-shaped literal in a test (build it at run time).
- **Pins are exact.** pi and pi-subagents are pinned in `package.json`; CI checks the installed
  version, lock integrity and provenance. A bump is its own change with a note of what the extension
  API changed. The Node version in CI carries a renovate marker; keep it that way.

## Tests and CI

`justfile` is the only task surface. `just check` is `fmt-check lint test leak`; `lint` is
`tsc --noEmit` plus a Python parse of `bin/`. `.github/workflows/ci.yml` runs `just fmt-check lint
test` on Linux, `just test` on macOS, the leak scan with the private term list, trufflehog,
actionlint and zizmor. Workflow actions are pinned by SHA with a version comment. New Python tools
go in the `python_tests` list in the `justfile` and, in `bin/`, carry the `python-floor` block
(Python 3.15; `bin/leak-scan` alone does not, so the git hooks never refuse a commit); new `*.test.ts` files are picked up by glob.

## Past fixes that show the bar

- "fix: enforce session capability ceilings for root delegation": a root-guard change that landed
  with a SEAMS.md paragraph, a new test file and a root test update.
- "fix: bound and clean up the nopush boot-id step": a launcher wrapper change that bounded the
  subprocess, removed only its own temporary file on failure, and added an installer test.
- "fix: hold idle wakes after an idle compaction; cap notices in compaction input": two timer
  states shared one slot; the fix added mock-timer tests shown red without the change.
- "fix(guard): refuse native child policy overrides without widening authority": a guard fix
  must not grant more than it refuses.

## Not a finding here

- `bin/loop-pi-install` writing launchers with a "Generated by ... Do not edit" header: they are
  produced at install time and are not committed.
- No formatter for TypeScript or Python; `just fmt` formats only the justfile.
- Absence of an issue or task id in commits and PRs: the maintainer tracks work privately.
- Guard bypasses through explicit `pushurl`, scrubbed environments, Git libraries or API writes,
  which SEAMS.md and `bin/loop-pi-nopush` state as out of scope.
- Large `extensions/SEAMS.md` or `package-lock.json` diffs on their own; read them, do not flag size.
